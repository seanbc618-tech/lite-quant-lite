# 质量卫星策略持续观察与 Paper-Dry 设计说明

## 一句话结论

本轮通过研究门槛的是两套质量策略变体：`base` 和
`reported_only`。下一阶段选择 `reported_only` 作为主要观察对象，
因为它在当前回测中表现更强，并且只使用 SEC 申报中直接披露的杠杆字段，
不依赖推导值，结论更容易审计和复核。

这仍然不是实盘策略。本阶段只新增持续压力报告和只读的
`paper-dry` 观察单，不改变现有 LightGBM 候选，不发送真实或纸面订单。

## 这个策略到底是什么

质量卫星策略不是追热点，也不是每天让模型重新猜涨跌。它试图找到经营质量
比较稳健的公司，用更慢的节奏持有：

1. 股票池使用当前 modern liquid100 provider 中的可投资股票，不选择
   `SPY` 或 `QQQ` 本身。
2. 每个月第一个可交易日重新选股一次。
3. 调仓时只能使用前一个交易日已经公开可见的 SEC 数据，避免偷看当天才
   披露的信息。
4. 每只股票从三个维度获得质量排名：
   - `roe_ttm`：过去十二个月净资产收益率，越高越好；
   - `cash_conversion_ttm`：过去十二个月经营现金流相对净利润的转换能力，
     越高越好；
   - `debt_to_assets`：负债占资产的比例，越低越好。
5. 三个排名等权合成质量分数，最多选择 9 只股票并等权持有。
6. 最多 9 仓是有意保留的边界：系统当前守住 10 个总仓上限，未来即使
   研究一个指数核心仓，也仍有一个位置可用。
7. 回测计入现有交易成本假设：买入 `0.05%`、卖出 `0.15%`。

## 两个版本的区别

| 版本 | 允许的杠杆数据 | 用途 |
| --- | --- | --- |
| `base` | SEC 直接披露值，或在缺失时由 `资产 - 股东权益` 推导的负债值 | 敏感性对照，观察扩大覆盖率是否影响结论 |
| `reported_only` | 仅 SEC 直接披露的负债/资产值 | 下一阶段主要持续观察候选 |

两套版本都必须通过门槛，才能说明策略结果不是依赖补算字段偶然出现的。
但真正值得拿来持续观察的是 `reported_only`，因为它的数据证据链最短：
申报事实到指标，再到持仓，较少引入额外假设。

## 本次为什么判定为通过

本次报告以现有 LightGBM monitor 的可比较时间范围为准：

- 比较起点：`2025-01-02`
- 最新 provider 交易日：`2026-05-22`
- 最新可安全评价交易日：`2026-05-21`
- 已知 benchmark 缺价：`SPY` 在 `2026-04-20` 缺少收盘价，报告明确使用
  现有 Qlib 报告一致的零 benchmark return 口径，不进行静默填充。

`reported_only` 的关键成绩如下，均已计入成本：

| 对比基准 | 时间窗口 | 年化超额收益 | 最大回撤 | 说明 |
| --- | ---: | ---: | ---: | --- |
| `SPY` | full | `+18.00%` | `-9.38%` | 长窗口相对宽基明显为正 |
| `QQQ` | full | `+11.09%` | `-9.07%` | 面对强势科技指数仍保持正超额 |
| `QQQ` | 63d | `+17.62%` | `-5.15%` | 近期压力窗口通过 |
| `QQQ` | 126d | `+22.85%` | `-9.07%` | 中期压力窗口通过 |
| `QQQ` | 252d | `+8.51%` | `-9.07%` | 一年窗口仍为正 |

`base` 也通过了相同门槛；但其 full 窗口相对 `QQQ` 年化超额只有
`+0.51%`，最大回撤为 `-24.64%`。相比之下，`reported_only` 不但不依赖
推导杠杆字段，长窗口的收益与回撤表现也更清楚，因此作为主候选。

本轮的“PASS”含义非常有限而明确：

- 允许进入持续研究观察；
- 允许生成只用于 dry-run 的目标持仓预览；
- 不允许自动替换现有 LightGBM 候选；
- 不允许进入可提交订单的信号目录；
- 不允许向 Alpaca 发送订单。

## 接下来要新增的观察链路

实现完成后，将提供两条独立命令。它们只围绕
`reported_only` 质量候选工作，不改变现有 ML 候选输出。

### 1. 持续压力监控

计划新增命令：

```bash
make monitor-quality-satellite
```

它将读取已经生成的基本面快照与 modern provider 价格，重新生成：

- `base` 与 `reported_only` 两种变体；
- `SPY` 与 `QQQ` 两个 benchmark；
- `full`、`63d`、`126d`、`252d` 四个窗口；
- 持仓数量、来源审计、交易成本和晋级门槛结果。

输出保留在本地研究缓存目录，例如：

```text
.cache/reports/quality_satellite_monitor_latest.md
.cache/quality_satellite/latest_holdings.parquet
```

监控命令不自动访问 SEC。这样每次压力测试都可复现，数据刷新行为也不会
隐含在一次普通报告运行里。

### 2. 隔离式 Paper-Dry 观察

计划新增命令：

```bash
make paper-dry-quality-satellite
```

运行顺序为：

1. 先更新质量策略压力报告；
2. 只读取 `reported_only` 最新组合；
3. 检查最新报告仍为 `Promotion gate: PASS`；
4. 检查仓数不超过 9、每个入选持仓的杠杆来源均为 `reported`；
5. 导出单独的 dry-run 观察文件；
6. 调用现有 `trade_v2.py --dry-run` 打印预览结果。

计划输出文件：

```text
.cache/signals/quality_reported_only_candidate_preview.json
```

文件必须带有：

```json
{
  "dry_run_only": true,
  "strategy": "quality_reported_only_candidate"
}
```

该文件属于研究观察产物，不属于正式信号输出，也不能用于提交订单。

## 数据怎么更新

价格数据与 SEC 基本面数据的刷新继续保持显式分离。正常观察时，运行已有
本地缓存即可。需要纳入新的 SEC 申报数据时，操作者先执行：

```bash
SEC_USER_AGENT="lite-quant-lite research <contact-email>" make fundamentals-sec
```

然后再执行质量监控或 paper-dry。文档不保存个人邮箱，运行时由操作者提供
符合 SEC 要求的联系方式。

## 与现有策略的隔离边界

本阶段必须保持以下约束：

- 不修改 `paper-dry-modern-low` 的 LightGBM 持仓预览；
- 不修改 `paper-dry-modern-core-satellite` 的核心/卫星试验；
- 不把质量策略混入 MLflow/Qlib 的现有模型实验命名空间；
- 不写入正式 `signals/` 订单来源目录；
- 不更改 `trade_v2.py` 的实盘或纸面下单权限边界；
- 任何 `FAIL`、缺失报告、超出仓数限制或存在非 `reported` 杠杆来源，都
  必须阻止质量策略 paper-dry 预览继续执行。

## 什么时候应该停止继续观察

持续监控并不等于永远保留候选。出现以下任一情形时，该策略应继续保持
研究状态，且停止生成新的 paper-dry 预览：

- 最新门槛报告为 `FAIL`；
- `reported_only` 最新组合超过 9 只；
- 最新组合包含非直接申报的杠杆来源；
- 相对 `QQQ` 的近期或中期表现重新明显落后现有 LightGBM 对照；
- 基本面覆盖范围、价格数据或 benchmark 缺价处理发生变化但尚未复核。

## 实现与验证范围

本阶段实现应尽量复用已通过验证的质量评分和成本回测逻辑，只增加隔离的
观察出口和可读说明：

- 在现有质量 runner 上增加监控报告/选择变体能力，或增加一个聚焦的包装
  脚本，而不复制评分逻辑；
- 新增从审计持仓生成 `dry_run_only` JSON 预览的脚本；
- 新增 Make 命令和 README 日常操作说明；
- 使用测试覆盖：只选择 `reported_only`、PASS 门槛拦截、9 仓限制、
  杠杆来源校验、dry-run-only 输出以及命令入口；
- 在当前本地数据上实际运行监控与 paper-dry，并把结果记录入库。

完成这一步之后，我们得到的是一条可重复观察、能被拦住、易于回头复盘的
质量策略研究线，而不是一个悄悄变成交易决策的黑箱。
